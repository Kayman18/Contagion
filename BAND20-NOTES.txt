BAND20 — 8 or 12 voices, dual-core render
=========================================
Install one of:
  release/FM1-Virooos-BAND20-12V.fwsc   12 voices (identity FM-1_15007512)
  release/FM1-Virooos-BAND20-8V.fwsc     8 voices (identity FM-1_15007508)
Source and tests included. Build: VOICES=12 ./build-band-firmware.sh (or VOICES=8).

What changed
- Voices: VC_VOICES is now a build setting (engine/voices.h, voice_count.h).
  The wave cache gets three clients per voice (36 at 12 voices); its client
  bitmasks are now 64-bit. Unison still has at most four layers per note, so
  twelve voices give three four-layer or six two-layer notes.
- Post stage on both cores. After the voices render, CPU0 used to sum them
  and run distortion, boost and EQ for both channels alone. Those keep
  separate state per channel, so CPU0 now runs the left channel while CPU1
  runs the right (a second worker job, protected by the usual timeout).
  Each core works on its own copy of the effect state and its own
  64-byte-aligned output; CPU0 copies CPU1's channel back after the join.
- Fused voice kernel. The per-sample oscillator, mixer, filter, saturation
  and envelope helpers are inlined into one SRAM kernel per voice span with
  a restrict output buffer (about 15 calls per voice-sample before). The
  out-of-line helpers moved to flash, used only by the profile page/tests.
- EQ: the compensated mid filter split all ten operands of its five exact
  products every sample. The coefficient splits now come from vc_eq_set and
  the history splits from the previous samples: 2 splits instead of 10.
- Merge: voices are summed voice by voice into each channel's buffer, so the
  fade checks no longer run for every voice on every frame.
- Per-voice render buffers are 256 frames (a 512-frame block renders as two
  halves); the profile synth and wave-sector scratch moved to the DSP pool;
  vc_pitch_bases (runs only when pitch changes) moved to flash.
- Overload relief (APP_OVERLOAD): after a block that used over 90% of its
  time, the next block fades out the quietest voice that is already
  releasing, with the 32-sample steal fade. Held notes are never cut. This is
  the only change that can alter sound, and only when the CPU is overloaded.
- The single-core TEST74 app (build-firmware.sh) keeps four voices and its
  SRAM helpers; its 67 simulator WAVs are byte-identical to before.

Exactness
- Built at four voices, all 60 BAND19 simulator scripts — including every
  one of the 650 factory presets with a chord, mod wheel and bend — hash
  bit-identical to BAND19 on every rendered float sample, with the same
  expectation results (tests/check-band20-exact.sh, reference hashes in
  validation/band19-float-hashes.txt). -ffp-contract=off keeps inlining exact.
- At 8 and 12 voices, sounds with four or fewer voices are unchanged; more
  notes now sound instead of stealing.
- With CPU1 as a real thread (tests/host/dc_pthread.c) and random start
  delays, all 63 scripts at 12 voices give the same hashes as single-threaded;
  ThreadSanitizer reports no races.
- Component runners: 42 run, same results as BAND19. EQ, boost and
  distortion match the original WASM (wabt). matrix-filters and test50 fail
  identically in BAND19 (pre-existing JS reference difference).
- tests/polyphony-8.txt / polyphony-12.txt: full chords, steals, two- and
  four-layer unison. tests/overload-shed.txt: shedding.

Hardware test
Hold 8, then 12 notes on INIT and on heavier presets (C0 AutoBendBC, D53
J.Edgar HS, C23 Digedi JS). GLO shows CPU % / PEAK % / XRUNS / DEADLINE /
VOICES. Report those for each build, and listen for clicks. If 12V overloads,
the 8V build has more headroom.
