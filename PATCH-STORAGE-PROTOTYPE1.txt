Native patch storage foundation — source checkpoint, 2026-11-14

Implemented a portable versioned patch record and16-slot bank codec.
Not yet wired to hardware Save/Recall; included BAND15 firmware is unchanged.
No flash has been written by this work. Effects remain deferred.

Record:189 bytes, including10-character ASCII name,126 native parameters,
all11 matrix routes (source,destination,amount), parameter-order fingerprint,
record length and CRC32. Byte order is explicit; C struct padding is excluded.
Parameters must fit the current native range. This saves native patch state,
not unsupported original Virus fields or excluded effects, MIDI controller
positions, held notes, oscillator phases or current cache contents.

Bank:16 slots in3044 bytes, including occupied-slot bitmask and outer CRC.
Fits the platform's3840-byte store-object payload. Slot replacement leaves
other records byte-identical. Empty-slot reads fail without modifying output.
Invalid records/banks are rejected rather than silently initialized or saved.
Platform A/B torn-write protection will be used when flash integration lands;
the codec itself does not implement or claim power-loss-safe persistence.

Tests:650 preset records round-trip after native range clamping, preserving
all controls, names and routes.1512 single-bit record corruptions rejected;
every truncated record rejected;3044 single-byte bank corruptions rejected;
16-slot save/recall and replacement isolation pass. Failed encode/decode
leaves outputs unchanged. ASan/UBSan pass. FM1 target object compilation passes.
Run bash tests/run-patch-record.sh and python3 tools/check_patch_schema.py.

Next: audio-owned snapshot handoff, flash save in acknowledged-mute main loop,
user-slot selection/recall and hardware power-cycle testing. These require
integration before this can be presented as working on-device patch storage.
