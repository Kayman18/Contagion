FM1 Virooos - post-TEST74 source audit checkpoint

No new firmware or DSP changes. Included firmware is unchanged TEST74.
New regression and audit scripts establish the actual remaining matrix work.

Initial oscillator phase, destination 88:
The captured original Matrix writes eff.oscInitPhase, but Voice.noteOn reads
ctx.patch.oscInitPhase. Voice.control never applies the effective value.
2540 tests over fixed initial phases 1..127, five route amounts and four
source levels confirmed unchanged start phases and control behavior. In 1524
cases the effective phase changed but the oscillators still used base phase.
Random phase 0 was not part of this fixed-phase sweep. Source inspection shows
it uses the same base-patch read. Do not add matrix-driven retriggering: that
would introduce behavior absent from the captured original.
Run: node tests/matrix-initial-phase.cjs

Wave selection, destinations 8 and 13:
14 retained presets configure non-neutral routes. Some source sweeps select
all 64 waves. The audit counts selections even when oscillator shape could
mask the wavetable contribution; it does not prove every route is audible.
It sweeps one source at a time over -1..1 with four note velocities and runs
the original Matrix. This is sampling, not exhaustive combined-route analysis.
Run: node tools/audit-wave-modulation.cjs
Detailed per-preset selections: validation/test74-wave-modulation-audit.json.

Current exact waveform architecture:
14 bands x 2049 samples x 4 bytes = 114744 bytes per complete wave.
Three resident caches occupy 344232 bytes.
Free normal RAM 7464 bytes; free pool 16228 bytes, total 23692 bytes.
Even combining those regions, one additional complete cache is 91052 bytes
short. Three caches support the static oscillator selections; they do not
provide a spare full cache for seamless replacement while playing.
app/app.c currently mutes and panics voices while loading replacements.
Connecting matrix wave selection through that loader would interrupt notes.

Storage measurement:
The existing 90426-byte coefficient bank already uses lossless compression.
Its reconstruction is performed outside playback while muted. It remains
appropriate for static selections and adds no decompression to sample playback.
All reconstructed tables total 7343616 bytes. A zlib level-9 test produced
6652381 bytes, versus a 282624-byte WAV partition. This rules out that tested
pre-expanded storage approach, not every conceivable lossless codec.
Data: validation/test74-wave-storage-audit.json.

Next implementation investigation:
A cache of individual frequency bands could use much less RAM than complete
waves (8196 bytes per band). It must support simultaneous voice pitches,
oscillators and shared oscillator-3 waves, reserve replacement space, and
retain exact table normalization. It also needs a bounded reconstruction
schedule and measured hardware headroom. Simply loading a requested band
synchronously in the audio callback is not an acceptable drop-in change.
No reduced-resolution tables, lossy codec or muted live-wave switching added.

Status correction:

remain genuinely unimplemented. Initial-phase matrix behavior is intentionally
inert to match the original. Patch import/persistence and the previously noted
