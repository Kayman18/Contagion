FM1 Virooos - band cache manager prototype 2

Source-only checkpoint. Firmware remains TEST74; experimental code is not
linked into the firmware or its audio callback.

Implemented experimental/band_cache.c and band_cache.h:
- Sixteen band slots serving twelve clients (four voices x three oscillators).
- Wave/band directory, reference counts and shared identical requests.
- A service job writes only an unreferenced output slot.
- Completed tables become eligible for explicit client commit.
- A client's old slot stays pinned until commit/release at a render boundary.
- New requests supersede older requests. Unwanted rebuilds can be cancelled.
- Failed coefficient loads retain existing client tables and can be retried.
- Round-robin job and replacement selection; no allocation.

Concurrency contract:
All cache API calls must be serialized by one owner or external exclusion.
The prototype does NOT yet implement atomic audio/main-loop publication.
A renderer may retain its current pointer until that client is committed or
released; those operations must not occur while it is reading that pointer.
No completed table is implicitly substituted into an active client.
The existing prototype budget bounds harmonic steps, not wall-clock time.
A new job calls the coefficient loader once; decoder cost is separate.

Validation:
Run bash tests/run-band-cache.sh after run-band-rebuild.sh if peak metadata
needs regeneration. ASan/UBSan passed 7868 invariant checks with 3000 rapid
request changes, 271 completed jobs and 242 cancelled jobs. Every pinned
buffer was compared byte-for-byte with the original source tables before
and after commit boundaries. Tests cover twelve distinct active clients,
staging-slot pressure, shared references, cancellation, invalid requests,
load failure/recovery, eventual settling after request churn, and release.
Evidence: validation/band-cache-prototype2.json.
The earlier all-896-band byte-exact reconstruction test remains included.

Measured host storage:
Sixteen band tables: 131136 bytes.
Cache metadata + builder + 2048-byte coefficient scratch: 2568 bytes.
Peak metadata: 256 read-only bytes.
Combined: 133960 bytes, plus the already-existing shared sine constants.
The 2568-byte measurement is for a 64-bit host. Target size, placement and
firmware integration have not yet been measured. These numbers are not a
claim that linked firmware RAM usage has already decreased.

Next:
Implement and test the audio/background request-and-acknowledgement handoff.
Then integrate exact decoding and table lookup behind a build option, check
target memory layout and measure hardware reconstruction timing. A stalled
or overloaded builder must never overwrite a playing table or make audio
wait for a synchronous reconstruction. The audible cache-miss policy still
needs to be evaluated. No live waveform modulation is enabled yet.
