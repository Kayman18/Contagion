FM1 Virooos - compressed-bank cache pipeline prototype 5

Source-only checkpoint. Firmware remains TEST74. The experimental loader,
cache and handoff are not yet bound to the synth's oscillator table handles.

Implemented:
experimental/band_bank.c reads the existing VCWAV001 compressed coefficient
bank, using the existing bounded LZ4 decode logic. Initialization verifies
header, directory and payload CRCs, entry bounds and the bank fingerprint.
The background load callback decodes one 2048-byte coefficient block into the
cache's existing scratch buffer and checks its per-wave CRC. No allocation.
The loader then supplies the exact precomputed normalization peak.

Normalization metadata is explicitly bound to this bank's byte length and
CRC, preventing a different valid coefficient bank from silently using stale
peaks. Regenerate peaks with tests/run-band-rebuild.sh, then generate the
embedded peak constants with tools/generate_band_peaks.py. This prototype
supports the current bank, not arbitrary user wave-bank imports.

Validation:
All 64 decoded coefficient blocks matched original float64 bytes exactly.
All 896 bands were requested, rebuilt, published and acknowledged through the
full compressed-bank -> cache -> handoff path. All 1835904 output samples were
byte-identical to captured source tables. ASan/UBSan passed.
Truncated banks and corruption in header, directory and payload were rejected.
A failed decode left the current audio table and selection intact; after valid
data was restored, the pending request completed correctly.
The standalone all-band reconstruction/budget test was also rerun and passed.
Run bash tests/run-packed-band-cache.sh.
Evidence: validation/packed-band-cache-prototype5.json and
validation/band-rebuild-prototype5.txt.

Target compilation:
All four background/handoff modules compile for pi32v2/r3. No atomic-runtime
helpers or heap-allocation dependencies appear in their objects. The builder
intentionally requires software-double arithmetic, as the original exact
reconstructor does; it must remain outside audio. A float finite check was
changed to bounded comparisons to avoid a new __fpclassifyf runtime dependency.
This is object-level verification, not a complete firmware link or hardware run.
Run JIELI_TOOLCHAIN=... bash tests/check-band-background-target.sh.
Evidence: validation/band-background-target-prototype5.json.

Memory/storage:
Compressed source bank remains 90426 bytes. No larger waveform bank is added.
Peak constants occupy 256 read-only bytes. Bank context is only a pointer and
length; target placement still needs linker verification. Decoder reuses the
2048-byte coefficient scratch already included in previous cache accounting.
Whole-bank validation runs at initialization, not in the audio callback.
Per-job decode/CRC work is outside the harmonic-step service budget and must
be included in hardware background timing measurements.
