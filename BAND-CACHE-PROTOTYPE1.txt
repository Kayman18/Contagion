FM1 Virooos - exact single-band reconstruction prototype 1

Source-only experimental checkpoint. Firmware remains unchanged TEST74.
experimental/band_rebuild.c is NOT linked into firmware or the audio callback.

Implemented:
A resumable single-band builder preserving the original float64 harmonic
addition order, float32 rounding before normalization, and float32 output.
No allocation, trigonometry or new waveform approximation. Caller-owned
coefficient/sine inputs and output buffer must remain valid during rebuilding.
Each service call has a harmonic-step budget and returns completion status.
Only completed buffers may be published to oscillators.

Exact normalization:
The original uses the full 128-harmonic waveform's float32 peak to normalize
all 14 bands. Generating a band independently must not normalize it to its
own peak. A 64-entry float32 peak table (256 bytes) removes the need to rebuild
the full waveform each time. experimental/wave-peaks.f32 is generated by the
test from the captured original float64 coefficients and sine constants.
The existing sine constants can be shared; this prototype does not need a
second sine table. Coefficients still need their existing 2048-byte scratch.

Validation:
Run bash tests/run-band-rebuild.sh.
All 64 waves x 14 bands = 896 bands, 1835904 samples, compared byte-for-byte
against data/source-waves.f32. All passed under ASan/UBSan. Service budgets
1, 17, 128 and 4096 were exercised, with further budget-37 comparisons on the
first/last waves. Zero-budget calls preserve progress. Invalid band/peak inputs
are rejected. No per-call harmonic-step budget was exceeded.
Evidence: validation/band-rebuild-prototype1.json.

Memory:
One output band: 8196 bytes (2049 float32 samples).
Coefficient scratch: 2048 bytes, reusable existing scratch.
Peak table: 256 bytes, suitable for read-only storage.
Builder state on this 64-bit host: 64 bytes. Target size still to be verified.
A replacement cache with 12 active references and 4 staging bands uses 131136
bytes for tables, versus 344232 bytes in the existing three complete caches.
That is 213096 bytes less table storage, BEFORE new metadata/publication costs.
This is a design budget, not measured linked firmware RAM savings.
The active bound assumes four voices times three oscillators, one band each.
Shared waves/bands can reduce actual demand. Old bands must remain pinned
until audio acknowledges their replacement.
Evidence: validation/band-cache-memory-plan.json.

Remaining before live-wave firmware:
1. A directory of (wave, frequency band), reference/pin tracking and staging.
2. Audio/main-loop handoff that never exposes partially rebuilt tables.
3. Cache miss and rapid-controller-change policy; no synchronous audio rebuild.
4. Verify band changes from pitch bend, glide, unison and oscillator 3.
5. Target memory layout and measured rebuild cost on FM1.

Cost limitation:
The builder takes 2048..262144 harmonic steps per requested band. A step may
perform two float64 multiplies and additions; the target's software-double
cost matters. The budget bounds iterations, not wall-clock time. Host tests
establish exactness and memory structure, not real-time hardware feasibility.
No claim of instant live waveform changes or a CPU improvement is made.
